# アフォーダンス図鑑

毎日ひとつのアフォーダンスの好例を、図とともに残す静的サイトです。Cloudflare Pages が `main` ブランチのルートにある生成済みの HTML を、ビルドなしで配信します。`data/entries.json` に一回ぶん足し、`python3 scripts/build.py` で HTML を作り直し、生成物ごと `main` にコミットします。

いま収録は 0 件です。第1回の予定日は 2026-11-16、公開時刻は日本時間の 20:00 ごろです。予定日を迎えても、この手順でオブジェクトを足すまでは空のままにします。下の「形式の見本」は説明用で、ファイルには入れません。

外部のフォント配信も、計測タグも使っていません。

## ファイル

| パス | 役割 |
| --- | --- |
| `data/entries.json` | 唯一のデータ。回を足すときは、この `entries` 配列だけを編集する |
| `images/` | 図版。`images/.gitkeep` はフォルダを残すファイルなので消さない |
| `scripts/build.py` | 生成スクリプト。標準ライブラリのみ。引数はない |
| `index.html` | 生成物。手で編集しない |
| `entries/NNN.html` | 生成物。`NNN` は回番号を少なくとも 3 桁でゼロ埋めした数（1 なら `001.html`）。1000 回目以降は桁が増える |
| `entries/.gitkeep` | 空の `entries/` を残すファイル。ビルドは消さない |
| `styles.css` | 手書きのスタイル。ビルドでは変わらない |
| `site.js` | 一覧の分野チップ。手書き |
| `favicon.svg` | サイトアイコン |
| `404.html` | 存在しない URL にアクセスしたときの案内 |
| `.nojekyll` | GitHub Pages の Jekyll を止める |
| `.github/workflows/check-build.yml` | コミット済み HTML と、ビルドし直した HTML が一致するか検査する |

## 新しい回を追加する

上から順に行う。

1. `main` を最新にする。`git switch main` のあと `git pull origin main`。作業ブランチは作らず、`main` に直接コミットする。フォースプッシュはしない。
2. 回番号を決める。`entries` が空なら `1`。そうでなければ、入っている `number` の最大値に 1 を足した整数。JSON では `"1"` ではなく `1` と書く。`1.0` は不可。
3. 日付を決める。その回が表す日を、日本時間の暦日で `YYYY-MM-DD` にする。20:00 は公開時刻であり、`date` に時刻は入れない。
4. 図を 1 枚か 2 枚、`images/` の直下に置く。サブフォルダは不可。推奨名は `images/001-1.jpg` と `images/001-2.jpg`（番号は手順 2 の 3 桁ゼロ埋め、拡張子は実際の形式）。拡張子は小文字の `jpg` `jpeg` `png` `gif` `webp` `svg` だけ。ファイル名に空白、`?` `#` `%` `\` 引用符、`<` `>` は使わない。ピリオドで始まる名前も不可。
5. `data/entries.json` の `entries` 配列の末尾に、次の節のオブジェクトを 1 つ足す。配列の途中に入れてもページの順序は変わらない（ビルドが並べ替える）が、運用では末尾に足す。見本オブジェクトは入れない。
6. リポジトリのどこからでも `python3 scripts/build.py` を実行する。終了コード 0 以外なら、標準エラーの `error:` 行を直し、もう一度実行する。成功するまでコミットしない。
7. リポジトリのルートで `python3 -m http.server` を実行し、表示された URL を開く。一覧でその回が先頭付近にあること、カードから開いたページで図が読めること、出典のリンク、前の回・次の回、一覧へ戻る、を確認する。
8. 次のファイルを同じコミットに入れる。
   - `data/entries.json`
   - 追加した画像
   - `index.html`
   - `entries/NNN.html`（`NNN` は手順 2 のファイル名）
9. コミットメッセージは `第N回 タイトル`（例: `第1回 平らな押板`）。`git push origin main` で送る。`--force` は使わない。
10. GitHub Actions の `check-build` が、生成 HTML とコミットの一致を検査する。失敗したら、手元で手順 6 をやり直して HTML をコミットし、もう一度 push する。HTML を手で直して合わせない。直す場所は JSON、画像、`styles.css`、`scripts/build.py` のいずれか。

チェック:

- `number` は既存の最大 + 1 で、ほかとかぶっていない
- `date` は `YYYY-MM-DD` の実在する日
- `src` のパスにファイルが実在する
- 本文 3 欄、出典 1 件以上、図 1 枚または 2 枚
- ビルドの終了コードが 0
- ブラウザで一覧・当該ページ・前後の回を見た
- 生成 HTML を手で編集していない

## データスキーマ

`data/entries.json` は UTF-8 の JSON オブジェクトで、キーは `entries` だけです。BOM はあっても読めるが、付けない。整形は 2 スペース推奨。ビルドは JSON を書き換えない。未知のキー、足りないキー、型の違い、空文字はエラーになる。

トップレベル:

```json
{
  "entries": []
}
```

配列の要素:

| キー | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| `number` | 整数 | はい | 1 以上。サイト内で一意。表示は「第N回」。ファイル名は少なくとも 3 桁のゼロ埋め |
| `date` | 文字列 | はい | `YYYY-MM-DD`。`2026-1-5` のような省略は不可。同じ日付が複数あってもよい |
| `title` | 文字列 | はい | その回の題。改行不可。先頭末尾の空白は無視する |
| `category` | 文字列 | はい | 分野。改行不可。文字列 `all` だけは予約なので使えない |
| `sections` | オブジェクト | はい | 下の 3 キーがすべて必要。ほかのキーは不可 |
| `sections.invite` | 文字列 | はい | 見出し「何がどう行為を誘っているか」 |
| `sections.contrast` | 文字列 | はい | 見出し「惜しい例・悪い例との対比」 |
| `sections.use` | 文字列 | はい | 見出し「使いどころのひとこと」 |
| `sources` | 配列 | はい | 1 件以上。並びがそのまま出典の順 |
| `sources[].title` | 文字列 | はい | 出典の表示名。改行不可 |
| `sources[].url` | 文字列 | いいえ | 付けるときだけキーを置く。空文字にしない。`http` または `https` |
| `images` | 配列 | はい | 1 枚または 2 枚。0 番目が図1、1 番目が図2。一覧のサムネイルは図1 |
| `images[].src` | 文字列 | はい | `images/ファイル名`。実在する空でないファイル。`..` や絶対パスは不可 |
| `images[].alt` | 文字列 | はい | 代替テキスト。図の中で、行為に関わる形が何かを書く。改行不可 |
| `images[].caption` | 文字列 | はい | 図の下に出す短い説明。改行不可 |

本文（`sections` の 3 つ）はプレーンテキストです。

- HTML タグは書かない。書いた場合はタグとして動かず、文字として表示される。
- 空行（改行だけの行を挟む）で段落が分かれる。
- 段落のなかの 1 つの改行は、表示上の改行になる。
- 先頭と末尾の空白（全角スペースを含む）は無視する。各行の両端の半角空白とタブも無視する。
- 制御文字は改行とタブ以外不可。

`title`、`category`、`alt`、`caption`、出典の `title` は 1 行。

分野は自由な文字列です。表記が一字でも違うと別のチップになります。既存の `category` とまったく同じ文字を再利用してください。まだ無いとき、または既存に当てはまらないときは、次から選ぶ。

- 扉と開口
- 道具
- 家電と操作部
- 公共空間とサイン
- 画面とインタフェース
- ゲーム
- 乗り物
- 遊具
- アクセシビリティ
- 自然と環境

文章の目安:

- 見たこと、または出典にあることだけを書く。
- 「何がどう行為を誘っているか」と「惜しい例・悪い例との対比」は、おおよそ 2〜5 文。「使いどころのひとこと」は 1〜3 文。
- 対比は、相手をけなさず、どこが惜しいか、どの印が誤るかを書く。
- 図は、行為に関わる形が分かる写真か図。顔が特定できるもの、許可のない資料は載せない。
- `alt` は見えない人への説明、`caption` は図の下の一文。同じ文でもよい。

## 形式の見本（投入しない）

次のオブジェクトは形の見本です。本文は記録ではなく、画像ファイルもありません。`data/entries.json` に入れないでください。入れると、画像が無いのでビルドが失敗します。

```json
{
  "number": 1,
  "date": "2026-11-16",
  "title": "（形式の見本。投入しない）平らな押板",
  "category": "扉と開口",
  "sections": {
    "invite": "ここに、何がどの行為を可能にし、どの印がそれに気づかせるかを書く。\nこの行は同じ段落の改行になる。\n\n空行を挟むと、次の段落になる。",
    "contrast": "ここに、惜しい例や、押す・引くを取り違える例を書く。",
    "use": "ここに、この見方をどこで使うかを短く書く。"
  },
  "sources": [
    {
      "title": "Norman, D. A. (2013). The Design of Everyday Things (Revised and expanded edition). Basic Books.",
      "url": "https://jnd.org/books/the-design-of-everyday-things-revised-and-expanded-edition/"
    },
    {
      "title": "URL がない文献は、title だけを書く。"
    }
  ],
  "images": [
    {
      "src": "images/001-1.jpg",
      "alt": "平らな金属板がついたガラス扉。板の面が押す位置を示している。",
      "caption": "押す面が、そのまま板になっている。"
    },
    {
      "src": "images/001-2.jpg",
      "alt": "棒状の取っ手が両面についていて、押すのか引くのかが板だけでは分からない扉。",
      "caption": "同じ形の取っ手が、押す側と引く側の両方についている。"
    }
  ]
}
```

## ページの決まり

ビルドが決めることなので、JSON 側で順序用のフラグは持たない。

- 一覧は新しい順。`date` の降順、同じ日は `number` の降順。
- カードは図1、第N回、日付（曜日つき）、題、分野。カード画像の代替テキストは空にする。題がリンク名になるため。
- 分野チップは「すべて」のあと、新しい回から見て、その分野が最初に出た順。URL の `#field=` のあとに分野名を URI エンコードして付けると、その分野だけを開く。JavaScript が無いときは全件を表示し、絞り込みだけ動かない。
- 各回ページは、一覧へ戻る、第N回、日付、分野、題、図（図1、図2）、三つの本文、出典、前の回、次の回。
- 前の回は `number` が一つ小さい回、次の回は一つ大きい回。日付の順ではない。端の回では「これが最初の回です」「まだ次の回はありません」。
- 出典に `url` がある項目は、`title` がリンクになる。
- 画像の寸法が読めるときは `width` と `height` を付ける。読めなくても、ファイルがあればビルドは成功する。
- JSON から消えた番号の `entries/NNN.html` は、ビルドが削除する。
- 同じ入力なら、同じ HTML になる。生成ファイルの末尾改行は LF が 1 つ。

曜日は JSON に書かない。ビルドが日付から出す。

## ビルドと検査

```bash
python3 scripts/build.py
```

Python 3.9 以上。追加のパッケージは要らない。

- 終了コード 0: 成功。標準出力に `生成しました: index.html、項目 N 件` と、書いたファイル名が出る。削除した HTML があれば `削除しました:` と出る。
- 終了コード 1: データがスキーマに合わない、または図が無い。標準エラーは `error:` で始まる。
- 終了コード 2: 引数を渡した。引数は受け付けない。

GitHub Actions（`.github/workflows/check-build.yml`）は、push と pull request で同じビルドを実行する。`index.html` か `entries/` がコミット内容と違えば失敗する。配信はしない。検査が失敗する典型は、JSON だけコミットして HTML をコミットし忘れたとき。

`styles.css` と `site.js` と `favicon.svg` は手書きなので、見た目だけ変えるときはビルド不要。`scripts/build.py` の HTML を変えたときは、ビルドして `index.html` と `entries/*.html` をコミットする。

## ローカルで見る

リポジトリのルートで:

```bash
python3 -m http.server
```

表示された `http://127.0.0.1:8000/` を開く。携帯の幅でも、図がはみ出さないこと、チップが押しやすいことを見る。

## 公開

GitHub リポジトリを Cloudflare Pages に接続する。本番ブランチを `main`、フレームワークを「なし」、ビルドコマンドを空欄、ビルド出力ディレクトリを `.` にする。ルートディレクトリは既定のリポジトリルートを使う。プロジェクトの「カスタムドメイン」に `affordance-zukan.mlabcraft.com` を追加する。

公開 URL は <https://affordance-zukan.mlabcraft.com/>。

## 既存の回を直す、消す

直すときは、そのオブジェクトと、必要なら画像を差し替え、ビルドし、JSON と画像と `index.html` と該当の `entries/NNN.html` をコミットする。`number` は URL になるので変えない。

番号を変えた、または回を消したときは、ビルドが古い HTML を消す。`git add -u entries` で削除もコミットに含める。使わなくなった画像も消してコミットする。

## 書体

端末に入っている書体だけを使う。

- 見出し: Hiragino Mincho ProN、Yu Mincho、serif
- 本文: Hiragino Sans、Hiragino Kaku Gothic ProN、Yu Gothic、sans-serif
